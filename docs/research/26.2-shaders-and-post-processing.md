# A. Custom shader requirements in 26.2

## A.0 Headline answers

| Question | Answer (evidence below) |
|---|---|
| Where do GLSL files live? | `assets/<namespace>/shaders/core/<name>.vsh` and `.fsh` (any subdir of `shaders/` works — resolved by `Identifier`, not hardcoded to `core`) |
| Include dir | `assets/<namespace>/shaders/include/<path>.glsl` — **the only** moj_import-able well-known location, plus path-relative quoted imports |
| Loader class | `net.minecraft.client.renderer.ShaderManager` (extends `SimplePreparableReloadListener<ShaderManager$Configs>`) |
| GL compile | Raw GLSL via `glShaderSource`/`glCompileShader` — **no SPIR-V on the GL path** |
| Vulkan compile | Runtime GLSL→SPIR-V via **shaderc** (`org.lwjgl.util.shaderc.Shaderc`), reflection via **SPIRV-Cross** (`org.lwjgl.util.spvc`) |
| Native libs ship? | **Yes.** LWJGL **3.4.1** `lwjgl-shaderc` + `lwjgl-spvc` natives for linux/macos/macos-arm64/windows/windows-arm64/windows-x86 are in the official 26.2 launcher manifest |
| Default backend | OpenGL first, Vulkan fallback (`PreferredGraphicsApi.DEFAULT`) |

## A.2 Real 26.2 core shader, in full (the `.vsh`/`.fsh` "header")

`assets/minecraft/shaders/core/gui.vsh` — a full startup shader with no imports:
```glsl
#version 330

// Can't moj_import in things used during startup, when resource packs don't exist.
// This is a copy of dynamicimports.glsl and projection.glsl
layout(std140) uniform DynamicTransforms {
    mat4 ModelViewMat;
    vec4 ColorModulator;
    vec3 ModelOffset;
    mat4 TextureMat;
};
layout(std140) uniform Projection {
    mat4 ProjMat;
};

in vec3 Position;
in vec4 Color;

out vec4 vertexColor;

void main() {
    gl_Position = ProjMat * ModelViewMat * vec4(Position, 1.0);

    vertexColor = Color;
}
```

`assets/minecraft/shaders/core/position.vsh` — a normal shader using imports:
```glsl
#version 330

#moj_import <minecraft:fog.glsl>
#moj_import <minecraft:dynamictransforms.glsl>
#moj_import <minecraft:projection.glsl>

in vec3 Position;

out float sphericalVertexDistance;
out float cylindricalVertexDistance;

void main() {
    gl_Position = ProjMat * ModelViewMat * vec4(Position, 1.0);

    sphericalVertexDistance = fog_spherical_distance(Position);
    cylindricalVertexDistance = fog_cylindrical_distance(Position);
}
```

Header rules, exactly:
- line 1 **must** be `#version <int>` (regex below). Vanilla uses `330`.
- imports follow as `#moj_import <ns:file.glsl>` lines.
- UBOs are declared inline with `layout(std140) uniform <BlockName> { ... };`
- samplers are plain `uniform sampler2D Sampler0;` etc.
- `#define` injection happens after line 1 (see A.5).

float linear_fog_value(float vertexDistance, float fogStart, float fogEnd) {
    if (vertexDistance <= fogStart) {
        return 0.0;
    } else if (vertexDistance >= fogEnd) {
        return 1.0;
    }

    return (vertexDistance - fogStart) / (fogEnd - fogStart);
}

float total_fog_value(float sphericalVertexDistance, float cylindricalVertexDistance, float environmentalStart, float environmantalEnd, float renderDistanceStart, float renderDistanceEnd) {
    return max(linear_fog_value(sphericalVertexDistance, environmentalStart, environmantalEnd), linear_fog_value(cylindricalVertexDistance, renderDistanceStart, renderDistanceEnd));
}

vec4 apply_fog(vec4 inColor, float sphericalVertexDistance, float cylindricalVertexDistance, float environmentalStart, float environmantalEnd, float renderDistanceStart, float renderDistanceEnd, vec4 fogColor) {
    float fogValue = total_fog_value(sphericalVertexDistance, cylindricalVertexDistance, environmentalStart, environmantalEnd, renderDistanceStart, renderDistanceEnd);
    return vec4(mix(inColor.rgb, fogColor.rgb, fogValue * fogColor.a), inColor.a);
}

float fog_spherical_distance(vec3 pos) {
    return length(pos);
}

float fog_cylindrical_distance(vec3 pos) {
    float distXZ = length(pos.xz);
    float distY = abs(pos.y);
    return max(distXZ, distY);
}

**What a mod must do (all verified against bytecode above):**
1. Ship `assets/<modid>/post_effect/<name>.json` in the mod's **client** resources (a `ResourceManager`-visible pack; Fabric mod jars are packs by default). Loaded automatically by `ShaderManager.prepare()` → `POST_CHAIN_ID_CONVERTER.listMatchingResources(...)`.
2. Ship the fragment/vertex GLSL under `assets/<modid>/shaders/post/*.fsh|.vsh`, referenced extension-less in JSON, e.g. `"fragment_shader": "<modid>:post/my_effect"`.
3. Read it at runtime with
   `Minecraft.getInstance().getShaderManager().getPostChain(Identifier, Set<Identifier> externalTargets)`
   and apply it with `PostChain.process(RenderTarget, GraphicsResourceAllocator)` (or wire it into the frame graph via `PostChain.addToFrame(FrameGraphBuilder, int, int, PostChain$TargetBundle)`).
   `externalTargets` must contain every target the JSON references that isn't declared under `"targets"` — vanilla passes `LevelTargetBundle.MAIN_TARGETS` (just `minecraft:main`) or `OUTLINE_TARGETS` (`main` + `entity_outline`); otherwise loading throws (`"Referenced external targets are not available in this context: ..."`).
4. There is **no registration API**: `PostChain` instances are cached inside `ShaderManager$CompilationCache.postChains`, and the only way a new effect becomes reachable is the JSON being present at reload time. A mod cannot inject a `PostChainConfig` object programmatically without mixin/access-widening.
   Vanilla's own consumers (`GameRenderer`, `LevelRenderer`) only use hardcoded `minecraft:` ids (`blur`, `creeper`, `spider`, `invert`, `entity_outline`, plus `transparency` which LevelRenderer requests), so a mod's own effect must be applied by the mod calling `getPostChain`/`process` itself.

# D. Executive summary for the port

1. **Shader authoring surface is source-compatible.** `.vsh`/`.fsh` at `assets/<ns>/shaders/...`, `#version 330` first line, `#moj_import <ns:file.glsl>` from `assets/<ns>/shaders/include/`, `layout(std140) uniform Name {...};` + `uniform sampler2D SamplerN;`. Identical to 1.21.11; several shaders (`gui`, `position`, `screenquad`) are byte-identical.
2. **What actually broke for shader authors in 26.2:** `sample_lightmap.glsl` extracted; `rendertype_text*` → `text*`; `item_entity_translucent_cull` → `item`; `entity_alpha`/`entity_decal`/`translucent_moving_block` removed; `entity.vsh` gained `#if`-guarded imports/samplers requiring defines (`PER_FACE_LIGHTING`, `NO_CARDINAL_LIGHTING`, `EMISSIVE`, `NO_OVERLAY`); `lightmap.fsh` UBO layout changed (`DarkenWorldFactor`→`BossOverlayWorldDarkeningFactor`, added `BlockLightTint`, `NightVisionColor`).
3. **Two backends.** OpenGL (default) compiles raw GLSL with the driver. Vulkan compiles GLSL→SPIR-V at runtime with **shaderc (LWJGL 3.4.1)**, target Vulkan 1.2, reflection via **SPIRV-Cross (`lwjgl-spvc`)**; native binaries for all 6 platforms are pulled by the vanilla launcher manifest. Vulkan path renames `gl_VertexID`→`gl_VertexIndex` / `gl_InstanceID`→`gl_InstanceIndex` via defines, and requires that `sampler` not be used as an identifier.
4. **Pipeline definition now goes through `BindGroupLayout`** (new class, one per UBO/sampler group) instead of the 1.21.11 flat `samplers`/`uniforms` lists on `RenderPipeline`. A mod builds `RenderPipeline.builder(...)...build()`, and to be auto-precompiled it must be visible in `RenderPipelines.getStaticPipelines()` — a `private static final` map, so a loader must widen/inject it.
5. **Post effects are unchanged in format and path** (`assets/<ns>/post_effect/<name>.json`, same 15 JSON keys, byte-identical vanilla files) but the Java side was rewritten onto `RenderPipeline` + `FrameGraphBuilder` (`PostChain.createPass` builds a `POST_PROCESSING_SNIPPET` pipeline at runtime, sampler names get `Sampler` appended, `SamplerInfo` UBO auto-injected). There is **no post-effect registry**; mods ship the JSON+GLSL as client assets and drive `ShaderManager.getPostChain(...)`/`PostChain.process(...)` themselves.
