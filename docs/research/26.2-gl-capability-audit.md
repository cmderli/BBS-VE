## 0. Headline findings

1. **Stencil is completely absent from the 26.2 abstraction — and was equally absent in 1.21.11.** Not a regression; it never existed. `grep -ril stencil` over the whole 26.2 tree returns 10 files, and every hit is the substring inside `DepthStencilState` / `VkPipelineDepthStencilStateCreateInfo` / `hasStencilAspect`. Zero stencil *operation* entry points exist. 1.21.11 returns **0 files** for `stencil`, `glStencil`, and `GL_STENCIL` across all 10291 classes.
2. **Raw LWJGL GL is fully reachable.** `com.mojang.blaze3d.opengl.GlStateManager` is `public` with **83 public static** methods wrapping raw GL, and `org.lwjgl.opengl.GL33C` (plus `GL43C`, `GL45C`) is on the runtime classpath. A `javac` compile test calling `GL33C.glStencilFunc`, `glStencilOp`, `glStencilMask`, `glGenerateMipmap`, `glGetTexImage`, `glDepthRange` **exited 0**.
3. **MRT is genuinely new in 26.2** (`MAX_COLOR_TARGETS = 8`, `glDrawBuffers`, `glColorMaski`; 1.21.11 had neither `glDrawBuffers` nor `ColorTargetState`).
4. **1.21.11's entity outline did not use stencil in 26.2 either** — 26.2 uses a separate `entityOutlineTarget` render target + `post_effect/entity_outline.json` post-chain.
5. **`Tesselator` and `VertexFormatElement$Type` were deleted.** `RenderType` moved package.
6. **The backend can be Vulkan at runtime** (`PreferredGraphicsApi{DEFAULT, OPENGL, VULKAN}`), which invalidates all direct GL calls.

**Therefore: raw `org.lwjgl.opengl.*` calls are only valid when the OpenGL backend is active. Any stencil/compute/`glGetTexImage`/`glDepthRange` work written against `GL33C` must be gated on the active backend** — detectable at runtime via `RenderSystem.getDevice().getDeviceInfo()` / the `GpuBackend` in use. On Vulkan the equivalents are `VkStencilOpState` (absent from MC's Vulkan renderer, so a mod would have to build its own `VkGraphicsPipelineCreateInfo`), compute via `VK_SHADER_STAGE_COMPUTE` (also absent), etc.
