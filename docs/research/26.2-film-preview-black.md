# Film editor preview is blank (26.2 port) — state of the investigation

## Symptom

The film editor's camera viewport (centre of the panel) draws a flat fill the colour of the editor
theme instead of the world. The panel, timeline, docks and buttons all render correctly.

## Established facts, each measured

| Fact | How it was measured |
|---|---|
| The snapshot texture is created, sized correctly and valid | `[BBS snap] texBefore=1514x426 want=1514x426 valid=true menu=true` |
| The blit into the snapshot runs every frame | `blitIntoSnapshot` entered 1825 times in one session |
| The preview does draw that texture | `UIFilmPreview.render` -> `batcher.texturedBox(texture, ...)` |
| `customSize` is on while the editor is open | `setCustomSize customSize=true w=1514x426` |
| **The read-back returned null every time** | `[BBS px] ... read-back timed out` |

## Fixed: the read-back never submitted its command

`Texture.pixelsFromTexture` and `Texture.readRegion` created the encoder inline and never called
`submit()`. A `CommandEncoder` only records; the queue reaches the GPU at `submit()`. The copy never
ran, the completion callback never fired, and the latch waited out its full timeout and returned
null. The upload path in the same class always submitted, and the class comment at the top of
`Texture.java` describes exactly this trap.

That single omission explains two symptoms that looked unrelated: the blank preview and video export
producing no file. Both now submit before awaiting (see the commit "SUBMIT the read-back copy").

**It did not fix the preview.** So the read-back was a real and separate bug, not this one.

## What is still unexplained

After the submit fix the preview is still a flat fill, so the snapshot is being filled with
something other than the world. The remaining candidates, in the order worth testing:

1. **The blit reads a cleared framebuffer.** If something clears BBS's render target between the
   world render and `captureAndRestore`, the blit faithfully copies a cleared image — which matches
   the observed flat fill. Check what clears the export target and when.
2. **The blit's source binding is wrong.** `blitIntoSnapshotDeviceNeutral` caches a borrowed view of
   the framebuffer's colour texture (`snapshotSourceView`). If that cache survives a target resize it
   points at the old texture, and the copy would again produce a flat result rather than an error.
3. **The world no longer renders into BBS's target while a menu is open.** `onWorldRenderBegin` still
   calls `toggleFramebuffer(true)` with a menu up; confirm the world actually lands there.

## Method note — read this before adding another probe

Three separate probes in this investigation printed nothing because their trigger conditions were
wrong (an absolute frame number that had already passed, a counter exhausted before the interesting
state was reached). Each silence was misread as "nothing is wrong here", which cost several rounds.

**A probe that prints nothing is not evidence.** Make every diagnostic probe report that it ran, or
key it on state rather than on a counter.
